## 원본 화면

지정함:

> 옮길 화면을 확인했습니다.
> 원본: `http://localhost:3000/preview.html?...`
> 목적지: Figma `abc123` 파일
> 단일 화면이므로 편집 가능한 레이어 방식으로 변환하겠습니다.

지정 안 했지만 컨텍스트로 추론:

> 옮길 화면이 명시되지 않아 현재 작업 중인 화면을 사용하겠습니다.
> 원본: `MaxGauge-VI / SQL Detail / default`

지정 안 했고 추론 불가:

> 어떤 화면을 Figma로 옮길지 필요합니다.
> 원본 페이지 URL, localhost URL, 또는 "현재 화면" 중 하나로 알려주세요.

## Figma 목적지

node-id까지 있음:

> 목적지를 확인했습니다.
> Figma file: `abc123`
> 배치 위치: `123:456` 근처
> 기존 파일 안의 지정 위치에 결과를 추가하겠습니다.

file URL만 있음:

> Figma 파일은 확인했지만, 넣을 위치는 지정되지 않았습니다.
> 새 페이지를 만들어 결과를 배치하겠습니다.
> 페이지 이름: `Code to Figma - <원본 화면명>`

목적지 없음:

> 결과를 넣을 Figma 위치가 필요합니다.
> Figma design 링크를 보내주세요. 특정 위치에 넣으려면 frame/page를 선택한 상태의 URL을 보내면 됩니다.

부분 확인 (제일 좋은 톤):

> Figma로 옮기기 전에 필요한 값 3개 중 2개를 확인했습니다.
> 확인됨: Figma 연결, 원본 화면
> 필요함: 결과를 넣을 Figma design 링크
> 링크를 보내주시면 기존 파일 안에 새 페이지를 만들어 배치하겠습니다.

## 디자인 시스템

사용자가 지정:

> Figma 연결, 원본 화면, 목적지를 확인했습니다.
> 디자인 시스템은 `Exem DS` 라이브러리를 우선 사용하겠습니다.
> 버튼, 입력, 탭, 테이블, 색상, 타이포는 가능한 경우 기존 Figma 컴포넌트/변수에 바인딩하고, 없는 요소만 새 레이어로 만들겠습니다.

지정 없음 — 목적지 파일에서 탐색:

> 디자인 시스템을 따로 지정하지 않아, 목적지 Figma 파일에 연결된 라이브러리와 로컬 변수를 먼저 탐색하겠습니다.
> 찾은 스타일/컴포넌트를 우선 사용하고, 매칭되지 않는 부분만 새 레이어로 구성하겠습니다.

탐색 결과 보고:

> 디자인 시스템 후보를 확인했습니다.
> `Exem DS` 라이브러리에서 Button, TextField, Tabs, Table을 찾았습니다.
> `SQL Plan Chart`는 대응 컴포넌트를 찾지 못해 새 레이어로 재구성합니다.
> 색상/간격/타이포는 목적지 파일의 연결 변수와 스타일을 우선 사용합니다.

아무것도 못 찾음:

> 목적지 Figma 파일에서 사용할 디자인 시스템 라이브러리를 찾지 못했습니다.
> 이대로 진행하면 편집 가능한 레이어는 만들 수 있지만, 기존 컴포넌트 인스턴스와 변수 연결은 제한됩니다.
> 사용할 Figma 라이브러리나 기준 frame이 있으면 알려주세요.

라이브러리 접근 불가:

> 지정한 디자인 시스템 라이브러리에 접근하지 못했습니다.
> 현재 가능한 선택지는 두 가지입니다.
> 1. 라이브러리 권한을 받은 뒤 다시 실행
> 2. 목적지 파일의 로컬 스타일만 사용해 진행
> 디자인 시스템 일관성이 중요하면 1번이 맞습니다.

## 실행 전 요약

> 실행 전 확인입니다.
> 원본: 현재 preview 화면
> 목적지: Figma `abc123`, node `123:456`
> 방식: 편집 가능한 레이어 변환
> 디자인 시스템: `Exem DS`로 추정됨

> 매칭 실패한 컴포넌트는 새 레이어로 만들고 마지막에 목록으로 보고하겠습니다.
