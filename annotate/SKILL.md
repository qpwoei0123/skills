# annotate

현재 작업과 관련된 로직의 이해 경로를 짧고 일관된 한글 주석으로 남기는 스킬이다.
목표는 주석을 늘리는 것이 아니라, 나중에 읽는 사람이 변경 이유와 주의점을 빠르게 찾게 하는 것이다.

## 불변 규칙

- 동작을 바꾸지 않는다. 주석이 아니라 코드 변경이 필요하면 보류한다.
- 주석은 항상 짧고 쉬운 한글로 쓴다.
- "무엇"보다 "왜", "조건", "주의점", "같이 봐야 할 로직"을 설명한다.
- 코드만 읽어도 명확하면 주석을 달지 않는다.
- 현재 작업과 무관한 파일까지 주석 정리하지 않는다.
- 기존 주석 스타일, 위치, 말투를 따른다.
- 오래되면 틀릴 구현 상세나 추측성 설명은 쓰지 않는다.
- 주석 때문에 코드가 더 복잡해 보이면 보류한다.

## 호출 형태

```text
/annotate
/annotate --go
/annotate -go
```

- `/annotate`: 현재 diff와 주변 로직을 보고 주석 후보만 제안한다. 승인 전에는 파일을 수정하지 않는다.
- `/annotate --go`, `/annotate -go`: 명확히 필요한 낮은 위험도의 주석만 바로 반영한다.

## 세션 경계

- 주석 수정 권한은 현재 사용자 요청 1회에만 적용된다.
- 이전 턴의 승인, `--go`, 주석 계획, 실행 결과는 다음 사용자 요청에 이월하지 않는다.
- 다음 작업에서 `/annotate`, `/annotate --go`, "주석 달아줘", "주석 정리해줘" 같은 명시 요청이 없으면 자동으로 주석을 추가하지 않는다.

## 기본 범위

기본 범위는 현재 diff와 그 diff를 이해하는 데 필요한 주변 로직이다.

1. diff가 있으면 변경 파일과 관련 호출부를 본다.
2. diff가 없고 사용자가 파일/함수/디렉터리를 지정했으면 그 범위만 본다.
3. 범위를 판단할 수 없으면 먼저 사용자에게 묻는다.

레포 전체 주석 정리는 기본 동작이 아니다.

## 분석 순서

1. 작업 범위를 확인한다.
   - `git status --short`
   - `git diff --stat`
   - `git diff --name-only`
   - 필요하면 `git diff`
2. 기존 주석 스타일을 확인한다.
   - 한글/영어 여부
   - 한 줄/블록 주석 사용 방식
   - 함수 위, 분기 위, 데이터 구조 옆 등 위치 습관
3. 작업과 연결된 로직을 추적한다.
   - 호출부와 피호출부
   - 상태 전이
   - 권한, 캐시, 이벤트, DB, 외부 API 경계
   - 테스트나 fixture가 설명하는 제품 규칙
4. 주석 후보를 고른다.
5. `/annotate`면 계획을 제안하고 멈춘다.
6. `--go`면 명확한 후보만 반영한다.

## 좋은 주석 후보

- 도메인 규칙이 코드만으로 드러나지 않음
- 분기 조건의 이유가 제품 정책, 운영 제약, 외부 API에 있음
- 같은 변경 때 같이 봐야 하는 파일이나 테스트가 있음
- 캐시, 이벤트, 권한, 상태 전이처럼 숨은 맥락이 있음
- 의도적으로 단순하지 않은 구현이나 우회가 있음
- 삭제하면 나중에 같은 실수를 반복할 가능성이 큼

## 쓰지 않을 주석

- 함수명, 변수명, 코드 흐름을 그대로 반복하는 주석
- "유저를 조회한다", "배열을 순회한다"처럼 코드만 읽어도 보이는 설명
- TODO, FIXME를 새로 만들지만 담당자나 조건이 없는 주석
- 특정 시점의 임시 상태를 영구 규칙처럼 말하는 주석
- 스타일을 맞추기 위한 대량 주석 정리

## 주석 작성 규칙

- 한 줄 주석을 우선한다.
- 한 줄이 길어지면 문장을 줄이고, 그래도 길면 블록 주석을 쓴다.
- 주석은 코드 바로 위나 같은 줄 중 기존 스타일에 맞는 위치에 둔다.
- "왜 필요한지"가 첫 문장에 보여야 한다.
- 주석이 필요한 코드가 너무 복잡하면, 주석보다 작은 리팩터링 제안을 우선 보고한다.

예:

```ts
// 초대 토큰은 재사용되면 안 되므로 조회와 동시에 만료시킨다.
```

나쁜 예:

```ts
// 토큰을 조회한다.
```

## `/annotate` 응답 형식

```text
주석 후보

1. <후보 제목>
   - 위치:
   - 남길 맥락:
   - 왜 필요한가:
   - 제안 주석:
   - 위험도:

보기:

1. 초대 토큰 만료 처리
   - 위치: src/auth/invite.ts:42
   - 남길 맥락: 토큰을 조회하는 즉시 만료시키는 이유
   - 왜 필요한가: 초대 토큰이 재사용되면 같은 링크로 여러 번 가입할 수 있어, 조회와 동시에 만료시켜 1회용을 보장한다.
   - 제안 주석: // 초대 토큰은 재사용되면 안 되므로 조회와 동시에 만료시킨다.
   - 위험도: 낮음

보류한 후보
- <주석을 달지 않는 이유>

검증
- 실행 예정:
- 생략:
```

`위험도` 값은 낮음/중간/높음 세 가지로 고정한다. `--go`는 이 중 낮음만 반영한다.

## `--go` 실행 규칙

`--go` 또는 `-go`가 있으면 다음 순서로 진행한다.

1. baseline을 기록한다.
   - `git diff --stat`
   - 명확한 검증 명령이 있으면 기록
2. 낮은 위험도의 주석만 반영한다.
3. 주석만 바뀌었는지 diff를 확인한다.
4. lint/format이 주석에 민감한 레포면 관련 검증을 실행한다.
5. 최종 보고에는 추가/수정한 주석 위치, 보류한 후보, 실행한 검증을 포함한다.
6. annotate intent를 종료한다. 다음 작업에서는 명시 요청 없이는 주석을 추가하지 않는다.

## 중단 조건

아래 상황에서는 `--go`여도 수정하지 않는다.

- 작업 범위가 불명확함
- 기존 주석과 충돌하는 내용을 확정할 수 없음
- 주석을 달수록 코드가 더 이해하기 어려워짐
- 제품/운영 규칙을 추측해야 함
- 사용자가 만든 기존 변경과 주석 대상이 안전하게 분리되지 않음

중단할 때는 이유와 다음 행동을 짧게 제시한다.
