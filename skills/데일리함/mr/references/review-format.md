# 리뷰 요청 제목과 본문

사용자 지시와 저장소 기여 문서를 우선한다. 그다음 저장소 PR/MR 템플릿을 쓰고, 기준이 부족한 부분만 최근 본문과 현재 diff에서 찾는다.

## 제목

별도 관례가 없으면 `<type>[(<scope>)]: <한글 요약>`을 쓴다. scope는 저장소가 쓰고 변경 영역이 분명할 때 붙인다. 대표 커밋의 문장을 그대로 복사하기보다 최종 변경 결과를 요약한다.

## 본문

문제와 변경 후 동작을 먼저 설명한다. 작은 변경은 짧은 설명과 필요한 검증 결과만으로 충분하다. 큰 변경은 의미 단위로 묶고 리뷰어가 판단할 중요한 지점을 덧붙인다.

- 파일 목록보다 접근 이유와 실제 동작 변화를 설명한다.
- 기계적인 rename·import·format 변경은 필요할 때 한 줄로 묶는다.
- 실행한 검증과 확인하지 못한 범위를 구분한다. 현재 변경과 무관한 검증을 나열하지 않는다.
- 실제로 남은 위험이나 판단할 문제가 있을 때만 설명한다. 빈 리스크·생략 항목을 채우지 않는다.
- 사용자 지시와 충돌하지 않는 저장소 필수 형식은 보존한다. 별도 요구가 없으면 체크박스 검증 목록을 새로 만들지 않는다.
- 최근 PR/MR을 참고했다면 목록만 보지 말고 해당 본문을 읽는다. 읽지 못했다면 참고했다고 주장하지 않는다.

본문을 API나 CLI로 전달할 때는 실제 개행을 보존한 임시 파일 또는 구조화된 입력을 사용한다.
