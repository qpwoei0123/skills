# 브랜치명 컨벤션

push 전에 현재 브랜치명이 레포 관례에 맞는지 판정할 때 읽는다.

## 판정 순서

1. CONTRIBUTING 등 기여 문서에 명시된 규칙을 사용한다.
2. 규칙이 없으면 최근 머지된 PR/MR의 head 브랜치 10~20개를 본다.
3. `dependabot/`, `renovate/` 같은 봇 브랜치는 표본에서 뺀다.
4. 표본의 약 70% 이상이 같은 형태일 때만 컨벤션으로 인정한다.

볼 수 있는 패턴:

- `feat/...` 같은 type prefix
- `name/...` 같은 작성자 prefix
- `ABC-123` 같은 티켓 번호
- kebab-case 같은 표기 방식

표본이 적거나 패턴이 섞였으면 "컨벤션 없음"으로 판정한다. 애매한 규칙을 새로 만들지 않는다.

## 판정 결과

- `부합`: 근거가 된 브랜치명 2~3개를 계획에 남긴다.
- `컨벤션 없음`: 표본이 섞였다는 근거만 남기고 진행한다.
- `확인 불가`: CLI·권한 등 실패 이유를 남기고 진행한다.
- `불일치`: 맞는 이름 하나를 제안하고 사용자 선택을 받는다.

## rename 안전 규칙

- 기본 호출은 계획의 마지막 승인 질문에 rename 여부를 포함한다.
- `--go`도 `rename 후 진행 | 현재 이름 유지 | 중단` 중 하나를 묻는다.
- `git ls-remote --heads origin <branch>`에서 이미 원격 branch가 확인되면 rename을 제안하지 않는다. 원격 branch가 갈라질 위험이 더 크므로 불일치 사실만 보고한다.
- rename은 push 전에 `git branch -m <new-name>`으로 실행한다.
