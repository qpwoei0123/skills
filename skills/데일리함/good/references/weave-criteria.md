# 같은 이유로 변하는 코드 묶기

한 정책을 바꿀 때 여러 위치를 항상 함께 수정해야 한다면 공통화 후보가 된다. 한쪽만 독립적으로 바뀔 수 있거나 제품 의미가 다르면 묶지 않는다.

## 적용할 근거

- 합친 뒤 실제 변경 지점과 이해해야 할 개념이 줄어든다.
- 공통 개념의 이름과 책임이 분명하고 사용처에서 흐름을 따라가기 쉽다.
- import 방향, 공개 계약, 번들·라우팅·서버 경계와 스타일 우선순위를 유지한다.

## 보류할 근거

- 한 번만 쓰는 코드나 모양만 비슷한 UI를 억지로 공통화한다.
- 작은 중복을 없애려고 큰 추상화, 순환 참조, 역방향 의존성을 만든다.
- 읽기 쉬운 로컬 코드를 멀리 보내거나 테스트 통과 외에 개선 근거가 없다.
