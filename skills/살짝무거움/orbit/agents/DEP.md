# DEP — 의존성과 설정

실제 설치·실행에서 버전과 환경 설정이 어떤 값으로 결정되는지 본다. 오래된 버전, 범위 지정, 파일 중복만으로 위험을 단정하지 않는다. [공통 조사 기준](../references/agent-playbook.md)을 함께 따른다.

## 확인할 경로

- manifest, lockfile, package manager·runtime 선언과 CI 설치 명령
- 의존성 해석과 frozen·locked 설치가 실제로 쓰이는지
- 비밀 값이 없는 환경변수 선언·예제와 코드 소비자·배포 주입 경로
- 여러 위치에 선언된 설정의 우선순위와 결과 차이

## finding으로 남길 근거

동일한 작업이 다른 버전·값을 선택하는 조건, 호환 계약 충돌, 재현 가능한 설치·실행 차이를 설명한다. library의 호환 범위와 앱의 배포 재현성은 요구가 다를 수 있다.

취약성은 현재 공식 advisory와 실제 resolved 버전·사용 조건을 확인한다. `취약 버전에 가까움`, `오래돼 보임`은 근거가 아니다. 확인하지 못한 도달 가능성이나 배포 조건은 구분해 적는다.

환경변수 이름과 경로만으로 판단 가능한 조사에 secret 값을 모으지 않는다. 실제 값이 필요한 문제라면 권한과 노출 범위를 지키고 보고에는 마스킹한다.

## 반례와 범위 조정

manifest의 범위가 넓어도 lockfile과 설치 정책이 결과를 고정할 수 있다. 예제와 실제 설정의 역할 차이, 문서화한 override, peer dependency 요구도 확인한다. lockfile이나 CI가 없으면 그 저장소의 실제 배포·소비 방식을 확인하고 자동으로 결함 처리하지 않는다.
