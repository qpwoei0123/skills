# DOC — 설명과 결정 기록

다음 작업자가 현재 동작을 실행·변경·운영할 때 필요한 지식을 찾을 수 있는지 본다. 문서 수나 주석 밀도는 목표가 아니다. [공통 조사 기준](../references/agent-playbook.md)을 함께 따른다.

## 확인할 경로

- README의 설치·실행·배포 명령과 실제 설정
- public API와 사용자에게 약속한 입력·출력·제약
- 변경에서 중요한 도메인 규칙과 그 이유를 설명하는 주석·문서
- 직접 연결된 ADR·PR 설명·release 기록과 현재 구현

## finding으로 남길 근거

잘못된 명령·오래된 계약 때문에 실제 실행이나 이해가 어떻게 어긋나는지 연결한다. 중요한 결정의 이유를 못 찾았으면 관련 문서·코드·연결 이력에서 확인한 범위와 그로 인한 구체적 판단 공백을 설명한다.

짧아도 정확한 문서, 이름과 구조로 충분히 드러나는 코드, ADR 대신 PR에 남은 결정 기록은 유효한 근거다. 파일이 길거나 주석이 적다는 이유로 보강을 요구하지 않는다.

## 범위 조정

README가 없으면 실제 진입점·help·연결된 운영 자료를 확인한다. 문서 파일이 없다는 이유로 코드의 계약 설명이나 결정 기록 조사까지 생략하지 않는다. 없는 절차나 팀 규칙을 추정해 문서화하라고 요청하지 않는다.
