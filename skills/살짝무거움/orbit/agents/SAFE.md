# SAFE — 변경 안전성

핵심 흐름의 계약이 바뀌었을 때 이를 발견할 검증 경로가 있는지 본다. 테스트 파일 수나 도구 도입 여부로 안전성을 대신 판단하지 않는다. [공통 조사 기준](../references/agent-playbook.md)을 함께 따른다.

## 확인할 경로

- 인증·결제·저장·공개 API 등 변경의 영향이 큰 진입점과 실패 조건
- 해당 동작을 검증하는 기존 unit·integration·E2E·타입 검사와 실제 assertion
- 로컬·CI·release 단계가 어떤 검증을 실제로 실행하는지
- 저장소가 명시한 필수 gate와 그 gate를 우회하는 경로

## finding으로 남길 근거

어떤 계약이 어떤 변경이나 실패 조건에서 검증되지 않는지 구체적으로 연결한다. 테스트 부재만 발견했다면 아직 후보이며, 명시적인 검증 약속의 누락이나 실제로 보호되지 않는 중요한 경로를 확인해야 한다.

이름이 비슷한 테스트를 찾았다고 검증 완료로 보지 않는다. 반대로 개별 파일의 대응 테스트가 없어도 상위 통합 검증이 같은 계약을 다루면 반영한다. coverage threshold 부재 자체는 결함이 아니다.

## 범위 조정

테스트가 없어도 CI·release·진입점의 계약을 볼 수 있다. CI가 없으면 다른 검증 경로와 사용자가 받아들인 운영 방식을 확인한다. 아무 보호 수단이 없는지 확인하지 않은 상태에서 전부 없다고 단정하지 않는다.

발행을 위한 분석 중에 새 테스트를 자동 작성하지 않는다. 필요한 다음 행동을 문제의 위치와 함께 제시한다.
