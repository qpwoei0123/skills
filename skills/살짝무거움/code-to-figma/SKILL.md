# code-to-figma

현재 구현을 Figma에서 이어 작업할 수 있도록 옮긴다. 원본, 목적지, 편집 요구를 현재 맥락에서 먼저 파악하고 변환·검증까지 이어간다.

## 입력과 도구

[입력 계약](references/input-contract.md)을 참고해 이미 주어진 값은 재사용한다. 빠진 값이 실제 결과를 바꾸거나 실행을 막을 때만 묻는다. 확인 순서를 고정하거나 네 가지 입력을 매번 사용자에게 요구하지 않는다.

- 원본: 지정 URL을 우선하고, 없으면 현재 작업 중인 화면을 사용한다. 대상이 여러 개라 좁힐 수 없으면 원본만 확인한다.
- 목적지: 지정 Figma 파일·node를 사용한다. 새 파일을 요청받았으면 해당 도구로 생성한다. 목적지가 전혀 정해지지 않았으면 결과를 쓸 위치만 묻는다.
- 결과: 기본은 편집 가능한 재구성이다. 사용자가 이미지 보관, 특정 DS의 instance·variable 연결 등을 지정했다면 그것이 완료 기준이다.
- 도구: 현재 노출된 Figma 읽기·쓰기·capture capability와 필수 skill 지침을 확인한다. 알려진 도구명만 보고 지원 기능을 가정하지 않는다.

파일 읽기 성공은 편집 권한의 증명이 아니다. 명시적인 권한 정보나 실제 쓰기 응답으로 편집 가능 여부를 판단한다. 인증·권한이 막히면 대상과 진행한 내용을 보존하고 정확히 필요한 접근만 안내한다. 불필요한 테스트 node를 권한 확인용으로 만들지 않는다.

로컬 서버가 필요하고 저장소의 실행 명령과 대상이 분명하면 기존 지침에 따라 준비한다. 다른 개발 서버를 종료하거나 source에 capture 코드를 영구 삽입하지 않는다. 사용자 환경을 직접 조작하는 도구는 그 환경의 동의 규칙을 따른다.

## 변환 방식 선택

화면이 여러 개여도 편집 가능한 레이어나 DS 연결 요구를 낮추지 않는다.

- DOM-to-design capture가 요청한 결과를 제공하면 이를 사용할 수 있다. 완료 후 실제 node 구조와 DS 연결 상태를 확인한다.
- DS instance·variable·style 연결이나 구조 통제가 핵심이면 편집 API로 재구성하거나 capture 결과에 필요한 매핑을 적용한다.
- 단일 이미지나 screenshot은 사용자가 그런 산출물을 요청했을 때 사용한다. 이를 편집 가능한 재구성으로 보고하지 않는다.

번들 `scripts/capture-url.ts`는 HTML-to-design script로 DOM을 제출하는 드라이버다. `capture`라는 이름을 픽셀 screenshot 업로드와 혼동하지 않는다. 제출 성공만으로 Figma 생성 완료나 DS 바인딩을 보장하지 않는다.

DS 연결 작업은 [탐색 기준](references/design-system-discovery.md)을 참고한다. 사용자가 지정하지 않았으면 목적지의 기존 instance·변수·연결 library부터 확인하고, 적합한 매핑이 없는 요소는 새 레이어로 만든 뒤 미연동 부분을 보고한다. 지정 DS 사용이 필수인데 접근할 수 없으면 그 요구를 조용히 대체하지 않는다.

실행 전에 원본 → 목적지, 방식과 중요한 제한을 한두 문장으로 알린다. 이미 요청받은 생성·변환에 별도 승인을 반복해서 요구하지 않는다.

## 실행과 확인

### 편집 API로 재구성

원본의 viewport·전체 높이·핵심 상태를 확인한다. 페이지 구조에 맞는 frame과 Auto Layout을 만들고 실제 매핑 근거가 있는 component·variable·style을 연결한다. 긴 페이지는 의미 있는 섹션으로 나누되 호출 횟수를 고정하지 않는다.

지정 node와 기존 콘텐츠를 보존하며 결과를 추가한다. 위치가 파일까지만 정해졌으면 새 페이지나 명확히 분리된 위치를 사용한다. 핵심 텍스트·레이아웃과 연결된 instance·variable을 결과에서 확인한다. 선택적 Code Connect 기능의 권한 부족은 변환 전체의 실패로 처리하지 않는다.

### DOM-to-design capture

현재 도구가 제공하는 capture ID 발급·제출·상태 조회 절차를 따른다. 번들 드라이버가 호환되는 경우 Node.js 20+, lockfile의 의존성과 Playwright Chromium을 준비한다. 이미 준비된 환경은 재설치하지 않는다.

```bash
npm ci
npm exec -- playwright install chromium
npm run capture -- --batch /tmp/figma-batch-jobs.json
```

batch 파일은 `[{ "captureId": "...", "url": "...", "label": "..." }]` 형식이다. 화면마다 별도 ID를 발급하고 생성 상태가 완료될 때까지 도구가 안내한 간격으로 조회한다. 드라이버는 제출 HTTP·본문 오류나 timeout을 실패로 반환하며, 후속 생성 실패와 함께 최종 결과에 반영한다.

성공한 frame을 목적과 화면 크기에 맞게 정렬한다. 열 수를 고정하지 않는다. 이번 실행이 만든 임시 node·빈 페이지라는 사실이 확인된 것만 정리한다. 일부 화면이 실패해도 독립된 나머지는 진행하고, 재시도 전에 이미 생성된 결과를 확인해 중복을 피한다.

## 전달

Figma 결과 링크와 완료한 화면을 먼저 준다. 편집 가능한 구조, 실제 DS 연결, 미연동 부분, 실패한 화면과 확인하지 못한 품질만 필요한 만큼 설명한다. 확인 응답이 없는 쓰기나 아직 진행 중인 capture를 완료로 세지 않는다.

상황별 짧은 표현은 [응답 예시](references/response-templates.md)를 참고한다. 예시 항목을 매번 전부 출력하지 않는다.
