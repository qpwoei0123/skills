# 응답 예시

원본·목적지·방식을 한 번에 설명하고 실제로 부족한 정보만 묻는다. 이미 받은 정보를 다시 채우는 표나 승인 문구는 만들지 않는다. 아래 예시도 상황에 필요한 부분만 쓴다.

## 실행 시작

> 현재 preview의 네 화면을 지정한 Figma 파일에 편집 가능한 레이어로 옮기겠습니다. 목적지의 기존 컴포넌트를 우선 연결하고, 대응이 없는 부분은 새 레이어로 만들겠습니다.

## 원본을 현재 맥락에서 선택

> 현재 작업 중인 SQL Detail 화면을 원본으로 사용하겠습니다.

## 새 파일 생성 요청

> 요청하신 새 Figma 파일을 만들고 현재 화면을 배치하겠습니다.

## 목적지가 아직 없음

> 원본 화면은 확인했습니다. 결과를 넣을 Figma 파일이 필요합니다. 기존 파일 링크나 새 파일 생성 여부를 알려주세요.

## 기본 DS 탐색에서 매핑 없음

> 목적지에서 대응하는 차트 컴포넌트를 찾지 못했습니다. 차트는 새 레이어로 구성하고, 확인한 버튼과 입력 컴포넌트는 연결하겠습니다.

## 필수 DS에 접근 불가

> 지정하신 라이브러리에 접근하지 못해 필수인 instance 연결을 완료할 수 없습니다. 원본 구조는 확인했습니다. 해당 라이브러리 접근이 필요합니다.

## 실제 쓰기에서 권한 오류

> 파일 내용은 읽을 수 있지만 결과를 추가하는 요청이 편집 권한 오류로 거절됐습니다. 목적지 파일의 편집 권한이 필요합니다.

## 일부 완료

> 네 화면 중 세 화면을 생성했습니다: <Figma 링크>. 설정 화면은 제출 후 생성에 실패했습니다. 생성된 화면은 편집 가능한 node 구조를 확인했고, 차트의 DS 연결은 남아 있습니다.

모든 성공 예시의 표현은 실제 도구 응답과 결과 확인에 근거해야 한다. 확인하지 않은 node 구조나 DS 연결을 예시 문구에서 가져오지 않는다.
