# ARCH — 경계와 의존 관계

저장소가 실제로 채택한 경계, 공개 API와 의존 방향을 본다. 레이어 이름이나 폴더 모양을 특정 아키텍처 채택의 증거로 취급하지 않는다. [공통 조사 기준](../references/agent-playbook.md)을 함께 따른다.

## 확인할 경로

- 진입점, package exports, 공개 API와 내부 구현의 호출자
- module·package·service 사이 import와 데이터·제어 흐름
- alias·barrel 뒤에 숨은 의존과 실제 cycle
- 공유 모듈이 특정 상위 기능의 변화에 묶이는 경로

## finding으로 남길 근거

명시한 경계·호환 계약 위반이나 초기화 실패, 빌드 제약, 순환 호출, 분리 배포 불가처럼 실제 영향을 연결한다. 같은 원인과 수정 범위인 문제만 합친다.

FSD가 명시된 저장소는 그 저장소가 따르는 규칙과 예외를 확인한다. 중간 레이어를 거치지 않았다는 사실만으로 위반이라고 하지 않는다. 일반 저장소에는 FSD 규칙이나 controller→service→repository 구조를 새 기준으로 강요하지 않는다.

`index.ts` 우회, type-only import, 테스트·fixture의 편의 의존을 런타임 경계 위반으로 단정하지 않는다. 순환이 보이면 실제 런타임·빌드 영향과 의도된 상호 의존인지 확인한다.

## 범위 조정

대표 공개 API와 변경 영향 경로부터 확인하고, 발견한 연결이 필요로 하는 범위로 넓힌다. 작은 모듈이나 단일 파일에 없는 계층을 만들라고 제안하지 않는다.
