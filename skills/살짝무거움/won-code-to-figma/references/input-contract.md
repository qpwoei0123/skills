# 입력 계약

필요한 정보는 원본, 목적지, 결과 요구다. 권한은 사용자가 채우는 입력 칸이 아니라 현재 도구로 확인할 실행 조건이다. 현재 대화에서 알 수 있는 값은 재사용하고 독립적으로 확인 가능한 정보를 묶어 수집한다.

## 원본

사용자 URL → 현재 작업의 화면 → 대상 확인 순으로 찾는다. localhost·preview URL, route와 화면 상태가 분명하면 별도 URL 제출을 요구하지 않는다. 로컬 서버가 없으면 저장소의 기존 실행 명령으로 준비할 수 있는지 먼저 확인한다.

로그인·특정 데이터·modal 상태처럼 결과를 바꾸는 조건이 있다면 재현 가능 여부를 확인한다. 볼 수 없는 상태를 다른 화면으로 조용히 대체하지 않는다. 브라우저나 사용자 환경 조작은 적용되는 동의 규칙을 따른다.

## 목적지

- Figma 파일과 node를 받았다면 그 위치에 추가한다. 기존 콘텐츠를 덮거나 삭제하는 요청으로 확대하지 않는다.
- 파일만 받았으면 새 페이지 또는 구분되는 위치를 선택한다. 위치 선호를 다시 묻는 단계는 필수가 아니다.
- 새 파일 생성 요청은 그 작업의 실행 권한으로 취급한다. 현재 도구의 새 파일 생성용 skill이 필요하면 읽고 생성한다.
- 기존 파일인지 새 파일인지도 알 수 없다면 목적지를 확인한다. 그동안 원본 구조와 필요한 도구는 조사할 수 있다.

일반적인 design URL은 `figma.com/design/<fileKey>/...`와 선택적 `node-id`를 포함한다. 실제 도구가 다른 유효한 Figma 링크를 지원하면 해당 파서·문서를 따른다. 문서에 없는 URL 형식을 추측해서 쓰지 않는다.

## 편집 요구와 디자인 시스템

기본은 편집 가능한 화면 재구성이다. DS가 지정되지 않으면 목적지에서 실제 사용 중인 component·variable·style을 탐색하고, 없는 부분은 새 레이어로 만들 수 있다. 이름이 같다는 이유만으로 연결됐다고 보고하지 않는다.

`반드시 이 DS`, `모든 화면을 instance로`처럼 필수 조건이 있으면 그 수준으로 결과를 확인한다. 접근 불가나 도구 제약으로 충족할 수 없는 요구만 설명하고 필요한 조정을 확인한다. 단순히 여러 화면이라는 이유로 screenshot으로 전환하지 않는다.

## 접근과 재개

가벼운 읽기로 파일 identity와 내용을 확인할 수 있지만 읽기 성공은 편집 권한의 증명이 아니다. 현재 도구의 명시적 권한 정보 또는 요청된 쓰기의 응답을 기준으로 판단한다.

인증이 없거나 목적지에 접근하지 못하면 이미 확인한 원본·목적지·요구를 유지한다. 인증 방법은 현재 도구에서 확인한 것만 안내하고 사용자에게 token을 대화에 붙여 넣게 하지 않는다. 접근이 복구되면 완료한 입력 단계를 반복하지 않고 이어간다.
