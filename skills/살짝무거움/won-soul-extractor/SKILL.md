# won-soul-extractor

샘플에서 반복되는 문체를 찾아 글에 적용한다. 글의 사실과 의도는 사용자의 것을 유지하고, 샘플이 뒷받침하는 만큼만 스타일을 구체화한다.

## 요청부터 처리

- 프로필 생성, 기존 글 변환, 새 초안 작성, 문체 채점 중 요청한 일을 수행한다. 모든 작업을 여섯 단계의 전체 파이프라인으로 만들지 않는다.
- `내 글`, `우리 브랜드`, 기존 프로필처럼 대상과 사용 권한이 분명하면 재확인하지 않는다. 허가가 불명확한 개인의 사적인 말투를 그대로 재현하려 할 때만 확인한다.
- 타인이 실제 작성·승인한 것처럼 속이는 요청은 수행하지 않는다. 분석이나 작성 주체가 분명한 일반 톤 초안으로 범위를 바꿀 수 있다.
- 본인의 공지·사과·공식 초안이라는 이유만으로 중단하지 않는다. 사실, 경험, 입장, 약속을 만들어 넣지 않는 것이 핵심이다.
- 현재 대화와 제공된 자료에서 독자·글 유형·핵심 사실을 먼저 찾는다. 중요한 사실이 없으면 그 부분만 묻고, 독립적으로 쓸 수 있는 부분은 진행한다.

## 샘플과 문체 지문

기존 프로필과 현재 제공된 샘플을 우선 쓴다. 샘플 수로 작성을 막지 않는다. 긴 글 하나로도 특정 글 유형의 임시 프로필을 만들 수 있고, 짧거나 서로 다른 유형의 샘플이면 적용 범위와 불확실성을 밝힌다. 추가 샘플은 결과를 바꿀 정보가 무엇인지 설명하며 요청한다.

다음 중 근거가 있는 특성을 추출한다.

- 말투와 종결어미, 독자와의 거리
- 문장 길이, 끊는 방식, 단락과 줄바꿈
- 자주 쓰는 어휘, 접속사, 감탄사·이모지
- 도입·전개·마무리와 제목 습관
- 글에서 드러나는 설명 순서와 결론 방식
- 글 유형이나 시기에 따른 차이

대표 표현은 짧게 인용해 특성의 근거로 연결한다. 글의 사고 전개를 실제 성격·신념으로 단정하지 않는다. 샘플에 없다는 이유만으로 `절대 안 쓰는 표현`을 만들지 않고, 사용자 지정 금지 표현과 추정상 어색한 표현을 구분한다.

프로필 저장·재사용을 요청받으면 [프로필 템플릿](references/profile-template.md)을 참고해 `~/.soul-extractor/profiles/<profile-id>.md`에 저장한다. 디렉터리가 필요할 때 `scripts/setup.sh`를 쓴다. 스킬 배포 폴더에는 런타임 데이터를 쓰지 않는다. 일회성 변환은 파일 저장을 필수 단계로 만들지 않는다.

## 변환과 작성

변환은 원문의 의미, 사실, 주장과 필요한 구조를 보존한다. 문체만 요청받았으면 주장을 추가하거나 새 논리로 바꾸지 않는다. 작성은 사용자가 제공한 사실과 입장 안에서 구성한다. 형식이나 분량을 지정했다면 함께 맞춘다.

문체의 특징을 과장해 반복하지 않는다. 특정 접속사·감탄사를 억지로 채우는 것보다 자연스러운 리듬과 설명 순서를 우선한다. 문체에 맞추려다 내용이 달라지거나 독자에게 필요한 정확성이 줄지 않았는지 마지막으로 확인한다.

사용자의 수정 피드백은 명시적 선호로 반영한다. 모델이 생성한 초안을 원래 저자의 새로운 샘플로 취급하지 않는다.

## 채점은 요청할 때

기본 출력은 요청한 프로필이나 완성된 글이다. 매번 완성도와 일치도 퍼센트를 붙이지 않는다.

사용자가 채점을 요청하면 [프로필 템플릿](references/profile-template.md)의 항목에 근거를 붙여 평가하고 `scripts/score.py`로 합산한다. 이 스크립트는 사람이 정한 항목 점수를 더할 뿐 문체를 자동 측정하지 않는다. 결과는 동일 프로필·기준 안의 참고 점수이며 저자 판별 확률이 아니다.

```bash
python3 scripts/score.py completeness 16 14 24 8 15
python3 scripts/score.py match 17 16 18 17 8 8
```

샘플이나 비교 근거가 없으면 숫자를 꾸며내지 않고 채점 불가 범위를 설명한다. 완성도 등급은 보강 필요성을 설명하는 참고이며 작성 허용 기준으로 쓰지 않는다.

## 전달

글을 요청받았으면 본문을 먼저 준다. 적용한 문체 특징이나 중요한 한계는 필요할 때만 짧게 덧붙인다. 프로필 작업이면 사용 범위와 근거를, 채점 작업이면 점수와 차이를 만드는 구체적 표현을 보여준다. 빈 점수표나 정형화된 부족한 점 목록을 채우지 않는다.
