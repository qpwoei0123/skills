# 스킬이 함께 쓰는 규칙

**규칙은 한 번 쓰고, 필요한 스킬에 자동으로 넣는다.**

토스의 코드 품질 기준을 작은 규칙으로 나눴다. 각 스킬 본문에 들어가므로, 설치한 에이전트가 다른 문서를 찾아 읽을 필요가 없다.

## 어디에 적용하나

| 스킬 | 적용하는 기준 |
|---|---|
| good · wow | 모든 규칙 |
| orbit | 예상대로 동작하는지, 함께 바뀔 코드가 모여 있는지, 변경이 어디까지 영향을 주는지 |
| review | 숨은 부수효과와 사람이 결정할 변경 관계 |
| commit · ship | 함께 커밋하고 제출해야 하는 변경 |
| code-to-figma · soul-extractor | 적용하지 않음 |

규칙이 있어도 스킬의 역할은 그대로다. 커밋을 요청했는데 코드 정리를 시작하지 않는다.

## 규칙을 바꾸려면

- **내용 수정:** [modules](modules/)에서 해당 규칙을 고친다.
- **적용할 스킬 변경:** [skills.json](skills.json)을 고친다. `modules`는 적용할 규칙, `application`은 그 스킬에서 쓰는 범위다. `["*"]`는 새 규칙까지 전부 적용하고, `[]`는 적용하지 않는다. 새 스킬도 여기에 등록한다.

저장소 루트에서 실행하면 스킬 본문이 갱신된다.

```bash
python3 scripts/sync_skill_rules.py --write
```

각 `SKILL.md`의 `common-rules` 영역은 자동으로 채워진다. 이 영역은 원본을 통해 수정하고, 스킬 고유 지침에 같은 내용이 있으면 중복을 제거한다. 실행 권한과 동작 보존 조건은 남긴다.

규칙의 의미가 달라졌다면 해당 스킬의 버전과 변경 이력도 갱신한다. 원본과 생성된 본문을 함께 커밋한다.

## 자동 반영

PR에서는 원본과 스킬 본문이 맞는지 확인한다. 불일치하면 위 명령을 실행해 갱신한다.

`main`에 올라오면 CI가 본문을 갱신하고 검사한 뒤, 바뀐 내용만 자동 커밋한다. 자동 푸시가 거절되면 CI에 실패로 표시된다. 이때는 생성된 변경을 직접 제출한다.

[토스의 코드 품질 기준](https://frontend-fundamentals.com/code-quality/code/)을 각 스킬의 역할에 맞게 재구성했다.
